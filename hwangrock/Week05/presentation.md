## 여러가지 pool들

### 스레드풀 

요청이 들어올 때마다 새로운 스레드를 만드는 대신,
미리 생성해둔 스레드들을 재사용하여 효율적인 병렬 처리를 수행

장점으로는 스레드 관련 오버헤드 감소,  
시스템 자원 낭비 방지,  
안정적인 동시성 제어 등이 있습니다.

예시로는 Java의 ExecutorService가 있습니다.

### 커넥션풀

데이터베이스나 네트워크 연결을 매번 새로 생성하지 않고,
미리 연결을 여러 개 만들어두고 재사용

장점으로는 DB 연결 생성 비용 절감,  
요청 처리 속도 향상,  
연결 누수 관리 용이 등이 있습니다.

예시로는 Spring Boot의 HikariCP와  
Apache의 Tomcat JDBC Pool이 있습니다.

### 버퍼풀

디스크에서 읽은 데이터를 메모리에 캐시해두어
반복적인 디스크 I/O를 줄이는 구조

장점으로는 캐싱으로 인한 I/O 속도 향상이 있습니다.

예시로는 MySQL InnoDB Buffer Pool와
PostgreSQL Shared Buffer가 있습니다.

### 프로세스풀

미리 여러 개의 프로세스를 실행시켜두고,
요청이 들어오면 해당 프로세스 중 하나가 작업을 처리.  
스레드풀과 유사하지만  
프로세스 단위로 격리되어 안전성이 높습니다.

장점으로는 스레드풀과 마찬가지로 병렬 처리 가능합니다.  

예시로는 Python의 multiprocessing.Pool이 있습니다.
